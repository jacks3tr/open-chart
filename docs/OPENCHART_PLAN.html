Build Plan · v1.0 · 29 August 2026

Arcline

A local, single-user, AAA-quality diagram editor for integration, architecture, and system-connectivity diagrams.

The thesis: the diagram is data, the canvas is a view, and the agent is a peer author. Every mutation — a mouse drag, a keyboard shortcut, an MCP tool call, a CLI batch job — travels through one op engine into one canonical IR. Dual editability is not a feature to build; it is what you get when there is only one way to change the document.

01 · The spine

One source of truth, one mutation path

The canonical IR holds semantics only — never geometry. Four independent origins emit ops into a single engine. Derived layers are a disposable cache. The resolved scene feeds three consumers, so the screen and the export cannot drift apart.

02 · Three tiers

Strict separation of truth, cache, and session

The rule that makes everything else work: geometry is never stored in the canonical layer. A corrupt derived cache must be unrecoverable-but-harmless, never a corrupted document.

T0
Canonical IR
Semantics, styles, tokens, provenance. The only thing agents read and write.
committed · diffable
T1
Derived layers
Positions, sizes, routes, text layout. Recomputable from T0, cached with a version hash.

T2
Ephemeral session
Camera, selection, hover, panel state. Kept in a separate file so the document stays git-clean.
session · gitignored
03 · Identity

Two identities per entity

The reason an agent can work with this document at all. UUIDs are unguessable; bare names are unstable. So every entity carries both.

id · address
aws.vpc.prod.subnet-a.api-gw.out
  • Hierarchical, lowercase, dot-separated
  • Mutable — renaming rewrites all references
  • Agent-addressable: it can be guessed
  • Surfaced in every text projection
uid · identity
u_01J9XK4Q7Z…
  • ULID — sortable, collision-free
  • Immutable — never changes, never renamed
  • The diff/merge key across renames
  • Never surfaced in text projections
Invariant enforced by the op engine: uid is identity, id is address. A rename_node op rewrites id in place, rewrites every reference — parent, children, port references in edges, layout overrides — and leaves every uid untouched.

Rules, enforced
  • Shapes get a 10–14% tint, never full saturation. Full-saturation fills on large shapes are the clearest marker of an amateur diagram.
  • Icons and logos stay full colour — they carry the recognition.
  • Gradients only on page backgrounds and container headers, max 2 stops, ≤8° hue shift.
  • Category = colour + icon + label. Never colour alone.
  • Max 6 semantic colours visible. The palette refuses a 7th and suggests a grouping.
  • Two elevation tiers only. Never a coloured shadow.
  • Radius: 8 nodes / 12 containers / 999 chips. No exceptions.
  • No glassmorphism — it breaks PNG/PDF export and destroys contrast.
Connectors & spacing
  • 1.5px uniform, #94A3B8, no taper.
  • Orthogonal with 8px corner radius; ~12px perpendicular jetty off each anchor.
  • Arrowheads small and solid, ~6px. Always directional — never double-headed.
  • Dashed = async, solid = sync, and the legend says so.
  • Chips sit on an opaque canvas-coloured rect so the line never runs through the text.
  • 8px base grid; 24px minimum gutter between siblings; 32px container padding; 16px icon-to-label gap.
  • Never mix icon stroke weights — Lucide/Feather or Phosphor, not both.
  • Hard floor of 10px type. Nothing smaller, ever.

06 · The lever

Beauty Pass — eleven steps, one undo entry

The single highest-leverage feature for the visual goal. Deterministic, idempotent, and exposed as an MCP tool — so an agent can author a correct but ugly graph and then have the app make it beautiful. Every step is an op, so the whole pass is inspectable in the journal.

01
Infer semantics — tag nodes by shape/name/label → tier → semantic colour
02
Infer hierarchy — detect containment, group into containers, infer missing boundaries
03
Assign ports — per shape definition; side chosen by flow direction
04
Auto-layout — ELK layered per container, INCLUDE_CHILDREN; force/radial for meshes
05
Route — orthogonal + obstacle avoidance, crossing minimisation, line jumps
06
Snap to grid — 8px grid, equalise sibling sizes, normalise gaps
07
Apply tokens — tints, radii, strokes, shadows, typography ladder
08
Semantics → style — sync = solid, async = dashed, protocol → chip
09
Generate legend — from colours, dash patterns, and icon set in use
10
Add title block — title, version, date, author, corner-anchored
11
Fit camera with margin
Non-negotiables it enforces: every icon has a label · every arrow has a direction · every colour has a legend entry · every diagram has a title block. Idempotence is asserted in CI: pass(pass(d)) ≡ pass(d).
07 · Agent surface

Four origins, one engine

MCP over in-process loopback HTTP (the Figma desktop precedent), a headless CLI for CI, and a file-watch path for agents that prefer to write files. All three compile to the same ops and hit the same engine. There is no second implementation.

Write path
  • Custom typed op array with stable ids — not RFC 6902 JSON Patch, not RFC 7386 Merge Patch. Array-index paths break under reordering and the ops aren't idempotent.
  • Upsert-by-id makes retries safe. Agents retry; create_node twice is one node.
  • dryRun by default on first contact — returns resolved ops, a rendered diff, and diagnostics without mutating.
  • baseRev optimistic concurrency; on conflict, return the current rev and a minimal diff so the agent can re-read and retry.
  • One transaction = one undo entry, so undo reverts exactly that agent turn.
  • Guardrails: 5,000-op cap, read-only mode, elicitation-gated confirmation above 25 deletes.
Tool surface
  • get_document_info · find_nodes · get_nodes
  • get_screenshot — the highest-value tool in the set. An agent cannot judge beauty from JSON; render → look → refine is the loop that gets agent output to the visual bar.
  • apply_operations — the one write tool
  • undo · redo · get_history · get_operations
  • apply_layout · apply_beauty_pass · set_tokens
  • export — SVG / PNG / PDF / D2 / Mermaid
  • Reads carry readOnlyHint. Never dump the whole document: find_nodes is the cheap lookup, subgraph is capped at 50.
Text projections
  • D2 — import + export. Best container + port fidelity of any diagram DSL (MPL-2.0).
  • Mermaid — export (+ limited import). Ubiquitous; loses ports and absolute positions.
  • Structurizr DSL — export. C4-native.
  • ELK JSON — internal handoff to elkjs.
  • Draw.io / Excalidraw — one-way ingest; keep geometry, lose semantics.
  • Round-trip law: parse(emit_d2(ir)) ≡ ir, asserted as a property test.
08 · Rendering

Canvas2D, three layers, baked effects

Following Lucid's own published findings: they flattened onto a single canvas with dirty-rect rendering in 2015, and moved selection handles to a second canvas because DOM overlays lead or trail the canvas by one frame in Firefox and Safari.

Three canvases
  • #bg — page, grid, static container fills. Dirty rect.
  • #main — shapes, connectors, text. Dirty rect from an rbush query — Lucid measured >1,000× speedup from this exact design.
  • #overlay — handles, guides, marquee, readouts. Full clear and redraw every frame.
  • DOM is used for exactly three things: app chrome, context menus, and one text-editing surface.
Chrome sprite cache
  • Each shape's chrome (shadow + border + fill + radius) is rendered once into an offscreen canvas, keyed by hash(shapeKind ‖ sizeBucket ‖ styleHash ‖ zoomBucket ‖ dpr).
  • Shadows cost nothing at draw time — they're baked, so shadowBlur's per-draw cost disappears.
  • Identical pixels on every platform, because no platform filter is ever used.
  • Architecture diagrams are enormously repetitive — 100 identical EC2 icons become one cached sprite.
  • LRU-bounded at 256 MB. One-off shapes fall back to direct draw.

10 · In one page

The five decisions this plan is really making

1 · Canvas2D, not SVG, not WebGL
Tauri ships three different WebViews with three SVG filter implementations and three font rasterizers, and WebGL on Linux can silently fall back to software with the renderer string masked. Pixel identity across platforms matters more than any other property — so every effect is baked into cached bitmaps rather than expressed as a filter.
2 · Chrome sprite cache
Shadows and gradients cost zero at draw time, and 10,000 shapes collapse into a few hundred drawImage calls. This is the primary performance lever and it is built in Phase 1, not deferred.
3 · Ops compile to Immer patches
Agents write semantic ops; undo is derived, exact, and free. No hand-written invert() anywhere in the codebase — they are the single largest source of undo bugs in editors of this class, because every new op silently needs a correct twin.
4 · Identity-keyed layout overrides
The only mechanism that reconciles auto-layout with human intent without fighting. Absolute pins (Graphviz pos, D2 top|left) are a trap: a re-layout either silently ignores them or fights them.
5 · One op engine, four origins
GUI, MCP, CLI, and DSL are the same code path, validated by the same code, journaled in the same stream, undone by the same keystroke. Dual editability is not a feature to build — it's what you get when there is only one way to change the document.
